# 五个 AI 工作席位任务说明

所有 AI 开发工具必须由仓库所有者自行连接 GitHub 私有仓库。此文件是可复制给各 AI 的任务说明；分支创建不代表外部 AI 已被启动。

## AI-1：平台安全与数据库
分支：ai/01-platform-security
负责：认证授权、租户上下文、RLS、复合外键、数据库迁移、管理员 MFA/RBAC、审计、安全测试、CI 安全检查。
首批任务：
1. 审计现有 migrations 和 app/auth；输出问题清单，不破坏现有注册/登录流程。
2. 修复租户隔离设计，证明不能通过伪造 tenant_id 或连接池上下文泄漏访问其他租户。
3. 最小化数据库角色权限；应用角色不得拥有业务表或 BYPASSRLS。
4. 增加迁移测试、跨租户负向测试、敏感信息扫描。
验收：跨租户读写全部拒绝；无租户上下文 fail closed；迁移在空库和上一版本库均可执行；无密钥进入 Git。

## AI-2：Telegram 克隆
分支：ai/02-telegram-clone
负责：MTProto 授权适配、账号连接、代理连接器、频道历史/实时克隆、消息映射、表情包克隆。
首批任务：
1. 盘点现有 Telegram 登录/账号代码，避免重复实现。
2. 实现 SOCKS5、MTProto Proxy、HTTP CONNECT 的连接测试和绑定；账号出口尽可能稳定，不使用代理轮换规避平台限制。
3. 实现授权源到授权目标的一对一路由；先建立实时接收，再历史回补，再按顺序排空缓冲。
4. 实现 Inbox 去重、源消息到目标映射、断点续传、编辑/删除能力边界、媒体组处理。
5. 表情包 MVP 先覆盖 API/MTProto 明确支持的类型，记录不支持项。
验收：断线/重启不重复成功投递；无目标发布权时拒绝启动；限速严格遵守 Telegram 返回的等待时间；不得绕过受保护内容。

## AI-3：Bot 与任务运行时
分支：ai/03-bot-runtime
负责：Worker、Outbox、任务租约、fencing token、资源预留、基础群发/定时任务、基础群管理。
首批任务：
1. 检查现有队列和任务实现，先写架构图与风险清单。
2. 实现 PostgreSQL transactional outbox；Redis 不作为任务唯一真相来源。
3. 实现 Worker lease、heartbeat、fencing token 和崩溃恢复。
4. 实现基础群发、定时任务、暂停/恢复/取消、每目标投递状态。
5. 增加资源准入和 429/backoff 处理。
验收：Worker 崩溃后可恢复；旧 Worker 不能继续写入；发送不确定状态不盲目重试；资源超限不接收新任务。

## AI-4：会员与商业化
分支：ai/04-billing-membership
负责：套餐/权益版本、订单、人工支付、支付适配器、USDT 核验、钱包和账本。
首批任务：
1. 盘点已有 billing、wallet、membership 代码和测试。
2. 保留价格快照与权益版本；余额不足返回准确差额。
3. 人工支付永远展示；微信/支付宝官方或易支付配置通过验证并启用后展示。
4. 支付回调幂等、TXID/转账事件唯一分配、多笔部分付款和超额处理。
5. 双重记账：每种资产独立平衡；已过账记录不可修改，只能冲正。
验收：重复回调不重复入账；同一链上事件不能分配两单；账本借贷平衡；订单履行失败不重新扣款。真实支付/链上联调需使用沙箱或测试网凭证。

## AI-5：前端与管理员
分支：ai/05-frontend-admin
负责：顾客端核心页面、超级管理员页面、API 客户端、教程入口、响应式 UI。
首批任务：
1. 先盘点仓库前端技术栈；如无前端，提出最小可维护选型并写 ADR。
2. 按 docs/API_CONTRACT_MVP.md 实现 API client、错误处理、登录状态和权限边界。
3. 实现顾客首页、Telegram 账号/代理、频道克隆、贴纸克隆、任务、会员/支付、钱包基础页面。
4. 实现管理员顾客/套餐/支付/任务/审计/IP 白名单核心页面。
5. 所有教程入口统一为“使用教程”，单按钮可配置文字、图文或视频；无教程时隐藏。
验收：移动端可用；不在前端保存秘密；所有写操作有加载/失败/重复提交保护；页面权限由后端再次验证。

## 提交要求
每个 AI 在自己的分支提交小而清晰的 commits，并向 integration/mvp 发 Draft PR。PR 描述必须列出测试命令和真实测试输出。不得声称未执行的测试通过。
