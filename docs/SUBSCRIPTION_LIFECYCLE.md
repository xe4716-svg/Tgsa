# TG SaaS V1.0 — 会员生命周期与任务恢复规则（2026-11-01）

> 状态：钱包交易、支付渠道适配器、自动续费设置/调度、站内通知、邮件通知和到期状态处理已进入代码仓库；真实商户联调、独立 TRC20 签名器生产部署、Telegram Bot 真实部署联调、运行任务暂停及续费后资源恢复仍需完成。
> 现有实现：迁移 004-009、app/billing/service.py、app/billing/router.py、app/billing/commerce.py、app/billing/payments.py 和 app/billing/automation.py。
> 重要边界：当前仓库尚无完整 Telegram 克隆任务执行 Worker，因此到期时权益门禁会回落 FREE 并记录过期/通知，但不能宣称已暂停所有实际 Telegram 发送任务；资源选择与安全恢复仍是后续实施项。

## 1. 产品不变式

1. 套餐：FREE / BASIC / PRO / ENTERPRISE，等级顺序固定；具体价格由超管配置并按订单快照保存。
2. 功能授权：先取当前有效套餐，再叠加该租户的超管覆盖配置；覆盖的开启/关闭值优先，数量上限为 `max(0, 套餐上限 + 调整数)`；套餐上限 `NULL` 代表不限，不接受数量增减对不限额度的重新定义。
3. 首版默认：FREE 不可频道/表情包克隆；BASIC 可频道克隆、不可表情包克隆；PRO 与 ENTERPRISE 均可，两项门槛均可由超管调整。
4. 正式到期即失去付费权限，无宽限期；保留账号数据、配置、历史消息映射、日志和订单，不因到期删除资源。
5. 到期后允许登录、查看历史及免费权益；但不能启动/继续任何付费后台任务。
6. 同级续费顺延；有效期内仅允许升级，不允许降级；到期后允许重新购买任意套餐。
7. 续费后超额资源不自动选择。需要租户选择额度内的账号/群/任务并通过权限、代理、授权和目标可达性检查，才允许恢复。
8. 续费后仅恢复因`MEMBERSHIP_EXPIRED`而暂停、且用户选择恢复的任务；人工暂停、封禁、风控、代理故障、权限丢失的任务不得自动复活。
9. 所有订阅变更、超管覆盖、扣款、退款、恢复操作可审计且使用幂等键。
10. V2.0 AI 群聊运营是独立可计费权益，不把 AI 配额混入 V1.0 克隆额度。

## 2. 会员状态与切换

| 事件 | 前置条件 | 原子行为 | 业务结果 |
|---|---|---|---|
| 首次购买 | FREE 或已过期 | 成功支付后创建新有效期 | 新套餐立即生效 |
| 同级续费 | 当前未到期 | 从原到期时间向后延长所买时长 | 不丢失剩余天数 |
| 到期后购买 | 当前已到期 | 从本次支付完成时间开始计时 | 可重新选任意套餐 |
| 升级 | 未到期且目标等级更高 | 计算剩余可抵扣价值，收差价，立即切换 | 新套餐完整周期从升级时刻开始，旧天数不叠加 |
| 降级 | 未到期 | 拒绝购买动作 | 保持原权益及有效期 |
| 到期 | `expires_at <= now` | 门禁立即降到 FREE，Worker 逐任务暂停 | 数据保留，不自动续跑 |
| 手动变更 | 平台超管操作 | 显式指定套餐/期限、事务审计 | 不生成虚构收款 |

在关键读/写路径必须使用数据库的时间判断有效期，不依赖定时任务是否准时执行。后台定时器更新`EXPIRED`状态用于运营报告与通知，不能作为授权唯一依据。

**状态区别：** `PAST_DUE`是扣费失败状态，不授予付费权限；`CANCELED`不等于“已到期”，取消自动续费仍允许当前已支付期间的权益持续至原到期日（实现时应区分自动续费配置关闭和订阅作废，不应简单将仍有效的订阅标为 CANCELED）。

## 3. 价格、升级折算与订单快照

- 价格精度：所有金额以对应币种最小单位整数保存，币种明确；不使用浮点数记账。
- 每笔会员购买保存：`order_id / tenant_id / plan_id / duration / currency / list_price / discount / actual_paid / price_version / paid_at / start_at / end_at / funding_source`。
- 续费按每次购买生成独立`subscription_term`，不能把多笔不同单价的续费合并成一个金额后均匀折算。
- 升级抵扣额 = 所有仍未消费的已支付会员期间，逐段按剩余时间计算的净支付额之和；免费赠送的权益不可兑换现金。
- 各段折算均使用整数运算并按向下取整；抵扣额上限为目标套餐本次应付价格，未用抵扣不提现/不转入余额；升级采用新完整周期，旧期间结束。
- 示例：原套餐支付 100 元、期限 30 天，正好剩余 15 天；目标套餐 200 元/30 天，则抵扣 50 元、补款 150 元，升级日重新开始 30 天。实际计算按 UTC 时间戳到秒/微秒，避免“按自然日”边界争议。
- 价格修改只影响未来订单，历史订单价和已有有效期不变；扣款前向客户展示**当前价格**与将扣金额。
- 需要退款/拒付的订单须从余额/权益账务层处理，不能直接改会员到期时间来“对账”。

## 4. 自动续费

- 默认关闭，租户主动开启，可随时关闭；只续当前套餐。
- 超管配置提前 1/3/7 天等扣款节点。系统按客户选用的提醒时区发送到期提醒；实际到期统一按 UTC 瞬时时间判定。
- 优先扣平台钱包余额；余额不足：发送站内通知、已验证邮箱通知，以及用户主动绑定后发送的 Telegram Bot 通知；创建待余额续费意图，**不得**产生负余额。
- 到账时若订阅尚未到期且仍启用自动续费，可对已有待处理意图尝试扣款；若已过期则不再自动扣款，用户须手动重新选套餐。
- 技术故障最多重试 3 次，按可配置间隔。余额不足与支付拒绝不应无限重试。
- 用户关闭自动续费后，撤销未提交扣款的待处理自动意图；不撤销已完成的会员有效期。
- 更改自动续费价格须按超管配置的等待小时数提前通知并提供关闭路径；等待期内不会扣款，扣款事务会再次校验最新价格版本。
- `unique(tenant_id, subscription_id, renewal_cycle)`以及资金流水唯一键，确保重复回调/定时执行不双扣。

## 5. 到期暂停与恢复

统一暂停原因优先级：`SECURITY_BLOCK > TENANT_SUSPENDED > MANUAL_PAUSED > CREDENTIAL_INVALID > PROXY_UNAVAILABLE > PERMISSION_MISSING > MEMBERSHIP_EXPIRED > QUOTA_EXCEEDED`。单个任务可持有多个阻断原因，恢复只移除对应已解除的原因。

任务执行前、发送前和每批次检查有效权益；到期事件发出后实时 Worker 停止后续发送，已在路上的 Telegram 请求不能保证瞬时撤回。调度器处理失败可重试，必须凭幂等键避免重复投递。

**恢复流程：** 收款成功 -> 新权益生效 -> 计算超额资源 -> 用户选择恢复集合 -> 逐项验证套餐、角色权限、Session、代理及目标发布权限 -> 仅通过的任务从上次独立断点续跑。未通过项保留暂停原因、产生明确提示，不自动加入群组、不绕过风控。

## 6. 超管权限覆盖（本轮已实现的基础能力）

- 数据表：`tenant_feature_overrides`，按 `tenant_id + feature_key` 唯一；采用 PostgreSQL RLS。
- `PUT /admin/tenants/{tenant_id}/feature-overrides/{feature_key}`：设置 `enabled_override`（true/false/null）、`limit_delta`（仅`max_*`）、必填`reason`。
- `DELETE /admin/tenants/{tenant_id}/feature-overrides/{feature_key}`：撤销例外，恢复套餐原值。
- 只有`platform_admin`可修改；变更前后值进入 `audit_logs`。
- `GET /billing/entitlements` 返回**套餐 + 覆盖**合成后的有效权益，不直接展示内部决策 SQL。
- 额度下降时，现有账号/任务数据不删除。后续 Worker 整合时暂停超额**运行**资源；新建资源严格按新限额拒绝。
- 重要：迁移`005_entitlement_overrides.sql`部署完成前不得运行新服务代码；现有数据库必须通过受控迁移执行，`docker-compose`不会对已初始化数据库卷自动补迁移。

## 7. 已实现的交易基础与后续接口

**迁移 006 与当前 API 已进入代码仓库：**

- 数据表：membership_plan_prices、tenant_wallet_accounts、wallet_ledger_entries、billing_orders、subscription_terms、platform_audit_logs。
- 套餐价格版本：超管设置价格时保留旧版本；订单保存套餐名称、价格版本、币种、原价、升级抵扣、实付金额快照。
- 钱包：每租户/每币种独立余额；CNY/USD 以分/美分计，USDT 以 0.000001 USDT 计；不同币种不混用。
- 钱包流水：只允许 SELECT/INSERT，禁止运行角色 UPDATE/DELETE；余额与流水在同一事务提交。
- 用户 API：GET /billing/prices、GET /billing/wallet、GET /billing/wallet/ledger、GET /billing/orders、POST /billing/purchases/quote、POST /billing/purchases。
- 超管 API：PUT /admin/plans/{plan_code}/prices/{currency}/{duration_days}、POST /admin/tenants/{tenant_id}/wallet/credits。
- 购买、续费、升级使用租户行锁和幂等键；余额不足时整笔事务回滚。
- 人工充值：管理员核实顾客付款后可直接加钱包余额，不要求顾客先建充值订单或上传截图。
- 手动会员分配修正：同套餐分配会顺延原到期时间；不会因默认 30 天而缩短无限期订阅。

**迁移 008 自动续费与通知、迁移 009 Telegram Bot 通知已进入代码仓库：**
- 用户可开启/关闭自动续费，选择续费币种、周期和 IANA 时区；默认关闭。
- 自动续费仅适用于有效的付费、有限期订阅；只续当前套餐，默认提前 3 天创建幂等续费意图。
- 自动扣款只使用平台钱包余额；余额不足进入 WAITING_FOR_BALANCE，钱包充值/人工入账后立即唤醒；已过期不再自动扣款。
- 技术异常最多重试 3 次，重试间隔由超管配置；价格变化按最新价格版本重新报价，并先发通知、等待配置时长后再尝试扣款。
- 站内通知、SMTP 邮件和 Telegram Bot 消息使用唯一去重键与独立 outbox；到期提醒默认 7/3/1/0 天，支持超管自定义提醒节点与平台/租户时区。
- 新增 API：GET/PUT /billing/auto-renew、GET/PUT /billing/notification-preferences、GET/POST/DELETE /billing/telegram-link、POST /webhooks/platform-telegram、GET /billing/notifications、POST /billing/notifications/{id}/read、GET/PUT /admin/billing/automation-settings。
- API 启动时启动自动续费/提醒/邮件/Telegram outbox Worker；通过 PostgreSQL advisory lock 确保多 API 副本只有一个执行者。

**仍待实现：** 真实商户沙箱/生产联调、退款/拒付/冲正、Telegram Bot 凭据与 Webhook 的生产部署联调、到期实际任务暂停、续费后的资源选择与 Telegram Worker 安全恢复。当前没有预置套餐价格，超管必须先配置价格才能购买。

部署注意：新数据库初始化会按文件名执行 001 至 009；已有数据卷不会自动执行新增迁移。先备份，再由数据库管理员按顺序执行尚未应用的迁移 006、007、008、009，最后部署应用版本。详细接口和金额单位见 docs/WALLET_AND_PURCHASES.md。

## 8. 核心验收场景

1. 到期前1秒可用付费权益，到期瞬间不可用；定时任务延迟不改变判断结果。
2. 同套餐提前续费顺延，到期后续费从新支付时刻开始。
3. 有效期内拒绝降级；升级只按未用净价值抵扣，不叠加旧天数。
4. 一笔支付回调重复10次只记一笔、发放一次权益。
5. 余额不足不变负数；余额到账但订阅已过期不会再次自动扣款。
6. PRO 个人账号配额由10增加到12，只影响目标租户；撤销覆盖回到10。
7. 手动暂停与会员到期同时存在时，续费不得解除手动暂停。
8. 续费后配额缩小的租户必须选择可运行资源；未选中的资源保留但停止。
9. 权限丢失、代理失败、新设备未检查通过均不能凭续费直接自动启动任务。
10. 跨租户访问覆盖、订单、操作日志失败；普通租户管理员不能设置超管覆盖。
