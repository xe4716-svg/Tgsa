# Legacy business schema adoption

The normal business migration runner refuses an existing untracked tgmate schema. Use scripts/adopt_business_schema.py only from a reviewed checkout with a dedicated migration owner, owner PG* credentials, and the ability to create/drop a disposable reference database.

Default operation is inspection only. The tool validates the 12 original SQL hashes against the import manifest, builds a temporary reference from the unchanged sources, compares structural catalogs, and removes its own reference database. It never reads customer row values. Reports contain object names/changed-field names and hashes, not function bodies or database passwords.

Comparison covers columns/defaults, constraints, indexes, triggers, RLS/policies, functions, types, sequences and database encoding/collation. Table data, arbitrary ACL differences and owner-name equality are excluded. Unsafe application ownership is separately rejected, including capabilities inherited by non-superuser login roles other than the migration operator. A structural match is not a full privilege, data-retention or production acceptance audit.

Before extending an old database, take an original full backup and inventory cluster roles and external keys. Stop other target-database clients and apply the root migration stream through 010, coordinating the cluster-wide runtime role credentials. Run inspection and review the report. --apply requires --backup-output pointing to a new private archive path. The tool creates an additional custom-format backup immediately before adoption, checks for changes again, verifies the catalog inside its ledger transaction, and writes the business ledger plus an explicit adoption audit with source/before/after/backup hashes. Existing backup destinations and existing ledgers are never overwritten. Application identities are not auto-linked. Container operators must mount a private persistent backup directory; do not save the only backup inside a disposable container.

The optional --reconcile-known-legacy recognizes exactly one historical shape: the two privacy CHECK constraints have legacy names but identical predicates, and a private five-argument auth_create_session overload remains alongside the current six-argument version. All other structures must match the reference. The old overload must be executable only by a safe NOLOGIN/non-superuser/non-bypass owner without other login-role membership. Reconciliation renames those CHECK constraints and removes only that unused private overload with DROP RESTRICT; the current authenticated login implementation continues using the six-argument function. No table rows are changed. Any dependent object, permission failure or mismatch rolls back the reconciliation and ledger together; its pre-change backup remains available.

The repository's historical tgmate_test was inspected only. Its 94 tables have this known historical difference and no root ledger. No adoption or schema modification was executed there. Tests instead initialize independent legacy-shaped databases, preserve a sentinel business row, reject unexpected drift and public legacy-function execution, test rollback on a dependent view, and verify backup hashes plus normal runner replay after adoption.

The actual historical test database was also backed up and restored into an independent copy. Root initialization, controlled reconciliation/adoption and runner replay succeeded there. All 94 business tables retained identical row counts and aggregate data hashes; the original database was not modified. Evidence is in docs/validation/legacy-copy.json, with private dump files excluded from source control. This is a test-data rehearsal, not a production cutover.

A database dump does not contain cluster roles, role passwords or separate Vault/Session encryption keys. Inventory and recreate required owner/runtime roles before recovery, supply credentials and matching key versions from the secret manager, and restore into a new database. The backup tool never drops an existing target. Keep dumps and diagnostics outside source control.
