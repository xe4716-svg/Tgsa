# TGMate MVP 验收清单

## 工程与安全
- [ ] 从 main 基线创建并维护 integration/mvp。
- [ ] 数据库迁移可在空库和升级库执行。
- [ ] 顾客/租户跨域读写测试全部拒绝。
- [ ] 管理员独立认证、MFA、RBAC 和 IP 白名单开关生效。
- [ ] 密钥、Session、Token 不进入代码、日志和前端。
- [ ] 备份恢复演练通过。

## Telegram
- [ ] 授权流程可在测试账号完成；2FA 和授权失败有明确处理。
- [ ] SOCKS5、MTProto Proxy、HTTP CONNECT 可测试、绑定和解绑。
- [ ] 频道源访问权和目标发布权在启动前检查。
- [ ] 历史回补与实时事件无交界漏消息（以测试数据验证）。
- [ ] 断线重启不重复成功投递；每路由独立进度。
- [ ] 文字、图片、视频、文件、相册按支持范围成功处理。
- [ ] 贴纸复制按支持类型工作，不支持项有记录。
- [ ] Telegram 429 按服务端等待时间退避，不规避限流。

## 两种独立群发系统
- [ ] 群发中心分别显示「机器人群发」与「TG 账号群发」两个入口。
- [ ] 机器人群发只能选择 Bot 身份并经 Bot API 发送。
- [ ] TG 账号群发只能选择已授权个人账号并经 MTProto 发送。
- [ ] 两种任务有独立列表、发送队列、并发预算、速率策略、统计和日志。
- [ ] 套餐权益和超管额度分别控制 bot_broadcast 与 account_broadcast。
- [ ] Bot 目标必须已添加 Bot 且具备发送权限；Bot 私聊须有有效启动/opt-in 资格。
- [ ] 个人账号目标必须是账号有权访问/管理的群组或频道；私聊仅限明确同意的对象。
- [ ] 发送身份创建后不可切换；故障时暂停，不自动回退到另一种身份。
- [ ] 不允许抓取陌生用户、无授权批量私信或通过账号/IP/代理轮换规避限速。
- [ ] Telegram 429/FloodWait 按平台返回时间暂停/退避；不确定投递不盲目重发。
- [ ] 每个目标独立记录状态；Worker 崩溃和租约过期恢复测试通过。
- [ ] 资源不足时排队或拒绝新任务，不使服务失控。

## 商业化
- [ ] 套餐价格快照和权益版本正确。
- [ ] 人工支付始终显示；自动支付配置验证成功后显示。
- [ ] 重复支付回调不会重复入账。
- [ ] USDT 网络、合约、地址、事件和确认数验证通过（仅对启用网络）。
- [ ] 钱包按资产分账；账本借贷平衡。
- [ ] 会员开通失败可重试履行，不重复扣款。

## 前端与运营
- [ ] 顾客端核心页面在手机端可用。
- [ ] 管理员后台权限按角色限制。
- [ ] 所有配置的教程入口统一显示“使用教程”。
- [ ] 文字、图文、视频教程展示可按按钮独立设置。
- [ ] 关键错误有可理解提示和 request_id。

## 发布门槛
- [ ] CI 通过，核心单元/集成测试通过。
- [ ] 安全、并发、故障恢复测试通过。
- [ ] Telegram 测试账号端到端联调通过。
- [ ] 支付渠道沙箱/测试网联调通过。
- [ ] 预生产部署和回滚演练通过。
- [ ] 无未处理的严重/高危安全问题。
