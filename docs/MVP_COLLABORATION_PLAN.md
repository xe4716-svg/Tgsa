# TGMate MVP 协作开发计划

## 目标
以当前 main 为基线，交付可供受控试点使用的 MVP；不把 MVP 等同于完整 V1.0。所有改动先进入各自 AI 工作分支，经测试和审核后合并到 integration/mvp，最终验收后才合并 main。

## 协作角色（5 个外部 AI 工作席位 + ChatGPT 总协调）
1. AI-1 平台安全与数据库：认证、租户隔离、RLS、迁移、审计、密钥边界、CI 安全检查。
2. AI-2 Telegram 克隆：MTProto 授权、代理连接、频道历史/实时克隆、媒体映射、表情包克隆。
3. AI-3 Bot 与任务运行时：Worker、Outbox、租约、资源准入、群发、定时任务、基础群管理和自动回复。
4. AI-4 会员与商业化：套餐权益、订单、人工支付、支付适配器、USDT 核验边界、钱包和账本。
5. AI-5 前端与管理员：顾客控制台、后台、教程入口、响应式布局、API 客户端和前端测试。
6. ChatGPT 总协调：维护业务基线/API 契约、拆分任务、审查 PR、解决跨模块冲突、验收和发布说明。

重要：这些分支已创建，但外部 AI 尚未被自动邀请或启动。必须由仓库所有者在 Claude Code、Codex、Gemini、Copilot 等工具中分别授权仓库并粘贴对应任务说明。GitHub 分支存在不等于 AI 已经在运行。

## MVP 必须包含
- 顾客账户、登录会话、租户隔离、管理员独立认证和审计。
- Telegram 账号授权基础（扫码/验证码/2FA 或受控协议文件导入），三种代理协议 SOCKS5、MTProto Proxy、HTTP CONNECT 的连接测试和绑定。
- 授权频道的一对一源→目标历史克隆与实时同步；至少覆盖文字、图片、视频、文件和相册；幂等、映射、断点、暂停/恢复、限速和异常记录。
- 获准来源的 Telegram 表情包复制 MVP：支持范围以实际 MTProto/API 能力为准，记录不支持项目，不绕过受保护内容。
- 基础群发/定时任务和基础群管理能力；任务有持久化状态、租约、资源准入和审计。
- 会员套餐/权益版本、订单、人工支付、已配置的支付适配器、钱包流水和基本财务核对。
- 顾客端核心页面、超级管理员核心页面、统一“使用教程”入口及文字/图文/视频三种可配置展示方式。
- Docker 测试部署、CI、备份与恢复演练、关键安全测试。

## MVP 暂不阻塞发布的后续功能
AI 吵群、AI CAPTCHA/真人挑战自动处理（挑战仍须人工完成）、高级多规则自动回复、复杂推广活动、多级财务自动化、自动提现、全量运营分析和高级 UI 动效。它们进入后续 V1.0 完整版迭代；已确定的业务约束仍保留，不因 MVP 删除。

## 交付阶段
A. 工程基线和安全；B. Telegram 账号/代理/克隆；C. Bot Worker；D. 会员支付；E. 前端后台；F. 集成测试和 MVP 试点。阶段可并行，但共享接口必须先遵循 API 契约。

## 真实状态报告
每项必须分别报告：代码已写、已提交分支、PR 已开、CI 通过、集成测试通过、外部真实联调通过、已部署。不得把设计或单元测试通过说成生产完成。
