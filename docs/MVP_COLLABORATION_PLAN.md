# TGMate 24 小时混合测试版冲刺计划

## 目标与边界
目标是在外部 AI 已接入、测试凭据/服务器可用的前提下，24 小时内尽力交付可部署、可登录、可操作的封闭混合测试版。该目标不是完整 V1.0，也不是生产上线承诺。若外部 AI 尚未启动或缺少 Telegram 测试账号/服务器，24 小时窗口无法真实开始。

## 十个并行工作席位
1. AI-1 平台安全/数据库。
2. AI-2 频道历史克隆/实时同步。
3. AI-3 Worker/Outbox/群发运行时。
4. AI-4 会员/订单/模拟支付/钱包。
5. AI-5 顾客端。
6. AI-6 Telegram 授权/协议号/代理。
7. AI-7 表情包克隆/媒体。
8. AI-8 超级管理员/教程中心。
9. AI-9 自动化测试/集成验收。
10. AI-10 Docker 测试部署/CI/可观测性。
ChatGPT 负责总协调、接口契约、PR 审查、冲突处理和验收报告。

## 24 小时节奏
- H0-H2：所有 AI 接入仓库；运行基线测试；确认依赖、环境、测试账号、部署主机；冻结 MVP API 契约。
- H2-H8：安全/授权/Worker/前端骨架并行；所有模块先交可运行纵切片，不追求完整功能。
- H8-H14：频道小范围历史+实时测试、代理连接测试、贴纸复制、群发任务、会员模拟支付。
- H14-H18：前后端整合；staging 部署；修复阻塞问题。
- H18-H22：跨租户、幂等、断线恢复、权限、移动端、冒烟测试。
- H22-H24：回归、备份/恢复检查、打包、发布说明和已知问题清单。

## 首日必须交付的纵切片
- 顾客可登录，管理员可独立登录并有 RBAC。
- Telegram 测试账号可授权（若提供真实测试凭据）；代理可测试并绑定。
- 对自有/获准源频道和目标频道进行小规模、低速的一对一历史克隆与实时同步；至少支持文本及可用的基础媒体类型。
- 贴纸包克隆仅在 Telegram 当前 API/MTProto 能力允许时纳入首日真实测试，否则明确标记下一阶段。
- 群发中心分别提供「机器人群发」和「TG 账号群发」入口；两者使用独立发送身份、队列、速率策略、任务列表和权益额度，不允许自动切换发送身份。
- Worker 能创建、执行、暂停、恢复两类群发任务，记录每个目标状态。
- 会员权益和模拟支付流程可操作，不接生产资金。
- 顾客端与管理员端核心页面可操作；教程入口统一“使用教程”。
- Docker staging 启动、健康检查、关键 CI 和安全冒烟通过。

## 首日不作为发布阻塞项
AI 吵群、高级群管理规则、全量自动回复、多级推广、自动提现、生产支付、生产 USDT 签名器、全功能分析报表、完整品牌动效。它们保留在后续 V1.0 路线中。

## 发布红线
- 不得将模拟支付标记为真实支付。
- 不得用真实顾客数据或生产密钥做冲刺测试。
- 不得绕过 Telegram 访问控制或限速。
- 跨租户隔离、Session 泄露、资金重复入账、Worker 重复投递属于阻塞问题，未解决不得对外开放。
- 未完成真实部署和真实测试，不得声称已交付可运行测试版。
- 测试版仅限邀请制测试，保留备份和回滚方案。

## 状态口径
逐项报告：已编码、已提交分支、PR 已开、CI 通过、集成测试通过、真实 Telegram 联调、已部署。24 小时是冲刺目标，不是保证。
