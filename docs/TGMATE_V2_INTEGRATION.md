## 如何开发

1. 本PR仅导入基线、静态CI和协作规范，不将两套app或数据库直接混合运行，不触发生产部署。
2. 本地V2测试证据：001～004h、94表、204项本地数据库/模拟适配器测试通过。不是GitHub新跑204项，也不证明实网或生产可用。GitHub当前新增检查只编译/解析和导入清单验证。
3. V2命令必须在workstreams/tgmate-v2目录执行。其app与根目录app不同，禁止混用PYTHONPATH、依赖或数据库初始化。不要在仓库根目录盲跑递归pytest收集两套测试。数据库必须独立，不能将V2 SQL直接执行到根工程库。
4. 第一张整合卡：盘点根工程与V2的身份/租户/RBAC、凭据、任务、会员/支付模型，形成明确复用边界和迁移映射；确认后才分模块迁入主工程。
5. 根工程已有邮箱认证、会员、支付和通知实现，代码/文档存在不等于已经执行测试。禁止按V2历史BACKLOG再重复重建；V2的004客服/002群发/003群管优先复用既有身份与商业底座。
6. 按现有ai分支领域协作：platform-security负责身份/RLS映射；bot-runtime负责客服/群管/群发；billing-membership核对权益/支付适配；frontend-admin负责操作台；qa-integration负责隔离数据库/整合回归；devops-deploy负责配置/迁移/恢复。这里只约定职责，不自动启动其他会话或邀请协作者。
7. 一张Issue对应一个feature/fix分支和一个PR，开发→针对性验证→自审→用户审核→合并。当前PR不自动合并，不改已有integration/mvp或ai分支。
