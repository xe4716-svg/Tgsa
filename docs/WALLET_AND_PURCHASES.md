# TG SaaS V1.0 — 钱包、充值与会员购买（阶段 5）

> 本文记录当前已经进入代码仓库的交易基础能力。钱包余额充值目前通过平台超管人工核实后入账；支付宝、微信、信用卡、易支付和 TRC20 的自动收款回调尚未接入，不应将它们标记为已上线。

## 1. 金额与币种

- 所有金额使用整数最小单位存储，禁止使用浮点数记账。
- CNY：amount_minor 单位为分；USD：单位为美分；USDT：单位为 0.000001 USDT。
- 一个钱包账户只对应一个币种；不同币种余额绝不相加。
- 升级抵扣必须与原会员剩余价值使用同一币种；不在平台内部猜测或自动换汇。
- 套餐价格由超管设置。仓库不预置虚构价格；未配置价格的套餐/周期/币种不可购买。

## 2. 数据模型（迁移 006）

| 表 | 用途 |
|---|---|
| membership_plan_prices | 套餐价格、周期、币种和价格版本 |
| tenant_wallet_accounts | 每租户、每币种的钱包余额 |
| wallet_ledger_entries | 不可变余额流水 |
| billing_orders | 会员购买订单与价格快照 |
| subscription_terms | 每笔已支付会员期限，用于续费顺延和升级折算 |
| platform_audit_logs | 全局套餐价格变更审计 |

钱包流水只授予运行角色 SELECT、INSERT，不授予 UPDATE、DELETE。每笔入账/扣款使用租户范围唯一幂等键；余额与流水必须在同一个数据库事务内更新。

租户钱包、订单、期限和流水均启用并强制 PostgreSQL RLS。每个请求在事务中设置 app.tenant_id，不能依靠前端传入租户 ID 来隔离数据。

## 3. 当前接口

### 用户侧

- GET /billing/prices：查看当前生效价格。
- GET /billing/wallet：查看各币种余额。
- GET /billing/wallet/ledger：查看最近钱包流水。
- GET /billing/orders：查看会员订单历史。
- POST /billing/purchases/quote：生成购买/续费/升级报价，不扣款。
- POST /billing/purchases：使用钱包余额购买、续费或升级。

购买请求必须携带客户端生成的 idempotency_key（至少 16 个字符）。同一租户重复提交同一幂等键和相同请求，只返回原订单；同一幂等键对应不同套餐、周期或币种则拒绝。

### 超级管理员侧

- PUT /admin/plans/{plan_code}/prices/{currency}/{duration_days}：设置某套餐、币种、周期的当前价格。每次调价都会生成新版本，旧订单保留原价格快照。
- POST /admin/tenants/{tenant_id}/wallet/credits：人工核实顾客付款后，直接为租户钱包入账。该操作不要求顾客先创建充值订单，也不要求上传付款截图；管理员必须填写原因和幂等键。
- 管理员钱包入账只允许正数 CREDIT；不得通过修改余额字段绕过流水。

## 4. 购买事务规则

1. 对租户行加锁，串行化同一租户并发购买。
2. 检查幂等键；已存在且请求指纹一致则返回原订单。
3. 读取当前价格版本和当前有效会员状态。
4. 检查是否降级；有效期内不允许降级。
5. 同套餐续费从当前到期时间顺延；已过期则从本次购买时间开始。
6. 升级计算尚未消费的已付款期限价值，按每段剩余秒数比例折算，整数向下取整；抵扣不超过新套餐价格，不足部分从钱包扣款。
7. 升级抵扣只可在同一币种内进行；剩余抵扣不提现、不转入钱包。
8. 钱包余额不足时整个事务回滚，不生成已付款订单、不变更会员权益。
9. 余额扣减、不可变流水、订单、会员期限、当前订阅和审计日志在同一事务内提交。
10. 成功后以新的会员权益立即生效；同一请求重试不会重复扣款或重复发放期限。

## 5. 到期与恢复边界

钱包购买成功只负责更新订单、会员订阅与会员期限记录。到期扫描、运行任务暂停、续费后资源选择和 Worker 恢复编排仍需后续模块接入。会员权限读取必须实时检查 expires_at，不能依赖定时器准时运行。

恢复任务时只允许恢复因 MEMBERSHIP_EXPIRED 暂停且用户选择的资源；手动暂停、安全封禁、代理故障、Session 失效和权限丢失不能被续费操作自动解除。

## 6. 当前未完成项

- 支付宝、微信、信用卡、易支付和 TRC20 自动收款与签名回调验签。
- 第三方支付事件唯一约束、回调幂等、金额/币种/商户订单核对。
- USDT 每订单独立收款地址、归集与链上确认。
- 退款、拒付、冻结与账务冲正流程。
- 自动续费设置、余额不足提醒、待续费意图与扣款调度。
- 用户端钱包充值说明/人工支付引导 UI。
- 任务到期暂停和续费后资源选择、权限检查、恢复 Worker。

这些项目未完成前，不得对外宣称已支持自动支付、自动提现或自动续费。

## 7. 部署

迁移顺序为 001 至 006。新 PostgreSQL 数据卷会由 Docker 初始化脚本按文件名顺序执行迁移。已有数据卷不会因为重新启动容器而自动执行新增迁移；部署前需备份数据库，并由数据库管理员在维护窗口执行 migrations/006_wallet_commerce.sql。迁移成功后再部署包含 app/billing/commerce.py 的 API 版本。

测试覆盖会员剩余价值比例折算、未来续费期限、过期期限、跨币种拒绝和购买请求指纹。GitHub Actions 对账务代码变更运行语法编译和单元测试。
