# 首发商业范围核对

历史首发设计提出“机器人群发、会员购买页面、USDT TRC20到账自动开通”。这是保留的商业需求，不代表功能已实现。套餐/钱包/商户或链上接入等尚未形成当前可验证完整闭环，见USDT_PAYMENT_DESIGN.md。

当前已有登录/权限和群发后端基础；没有完成会员购买、订单支付、链上确认、对账及自动开通。已有001会员/权益表优先复用，不能另造平行系统。人工开通只可作为本地测试手段，不得冒充自动支付首发验收。

实施顺序：稳定数据库与权限 → 管理后台/权益展示 → 订单与支付账本 → 支付接入与异常对账 → 原子开通/续期 → 测试支付和群发闭环 → 用户审核。暂不选定收款商或生成真实收款地址。

商业首发与本地可测试MVP分别验收。后续审核时需确认具体套餐、价格、收款方式与外部服务条件；当前按保留需求规划，不擅自删减，也不为未完成支付功能安排上线。
